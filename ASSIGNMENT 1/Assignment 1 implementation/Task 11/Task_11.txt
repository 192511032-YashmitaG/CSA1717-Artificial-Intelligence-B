TASK 11 – FINAL DESIGN RECOMMENDATION

For the simplified equal-cost graph, BFS is the safest default when the robot must obtain a route with the fewest moves. It is complete on a finite graph and returns a shallowest route, but its queue can become large as the hospital expands. Iterative DFS uses a smaller active stack in the experiment but can return a longer route and its result depends on neighbour order. Recursive IDDFS finds a shallowest route with low search-stack memory, but it repeats work at earlier depth limits.

The actual scenario assigns travel-time costs to corridors and lifts. Therefore, the deployed route planner should use uniform-cost search (Dijkstra's algorithm) for non-negative edge costs, not plain BFS. It expands the lowest accumulated-cost route first and returns a minimum-travel-time path. The weighted test in Task 8 demonstrates this choice.

Preprocessing: construct and validate the adjacency list, including current corridor availability and travel-time estimates. This costs O(V+E) time and storage. Rebuild or update only affected edges when the hospital layout changes. For very large deployments, use a priority queue, efficient map representation and route replanning when edge conditions change.

Final decision: use uniform-cost search for the weighted hospital route, retain BFS as a baseline for equal-cost testing, and use DFS/IDDFS only where reachability or low-memory exploration is more important than weighted-route optimality. The one-million-state benchmark is evidence for the simplified graph, not a guarantee for every hospital layout.
