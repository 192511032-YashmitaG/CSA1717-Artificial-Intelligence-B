TASK 3 – MATHEMATICAL TIME AND SPACE COMPLEXITY

Let b be the branching factor, d the depth of the shallowest goal, m the maximum depth, V the number of vertices and E the number of edges. For a regular tree, level i contains b^i nodes.

BFS
Nodes generated through depth d: 1 + b + b^2 + ... + b^d = (b^(d+1)-1)/(b-1), for b != 1. Each generated node is queued once and each reached node's outgoing edges are examined at most once. Time is O(V+E) for graph search; on a regular tree up to the goal level it is O(b^d). The queue can hold a whole level, so space is O(b^d). Adjacency-list preprocessing costs O(V+E) time and O(V+E) space. Total time includes this preprocessing plus search.

Iterative DFS
In a finite graph with a visited set, each vertex is pushed at most once and each edge is examined at most once. Time is O(V+E), worst-case O(b^m) when expressed as a tree search. The explicit stack and visited/parent structures use O(V) graph-search memory; without a global visited set, tree-search stack memory is O(bm). It may stop much earlier if the goal is found early, but worst case explores the whole reachable graph.

Recursive IDDFS
At limit l, depth-limited search may visit 1+b+...+b^l nodes. Repeating limits 0 through d gives total calls S = sum(l=0..d) sum(i=0..l) b^i. Rearranging by depth gives S = sum(i=0..d) (d-i+1)b^i. The deepest level dominates for b>1, so time is O(b^d) (with a constant-factor revisit overhead). The recursion path stores at most d+1 nodes, so search space is O(d), excluding the graph and any path-cycle set. Preprocessing remains O(V+E) time and space.

Weighted-cost note
If moves have different travel times, depth is not the same as cost. Uniform-cost search expands in increasing path cost. With non-negative costs and minimum edge cost epsilon, a standard bound is O(b^(1+floor(C*/epsilon))) generated nodes, where C* is the optimal solution cost; its frontier may have the same order. The actual graph-search bound also depends on V and E.

The total implementation memory includes the adjacency list, visited/parent map, and frontier; quoting only frontier memory would understate the complete program's memory use.
