TASK 12 – RE-EVALUATE AND ADAPT THE DESIGN

A. Impact analysis
The original problem assumed one known current location. After the sensor fault, the robot knows only that it is at one of k possible junctions. Its knowledge must be represented as a belief state: a set of possible physical locations. The problem is now partially observable.

B. Evaluate the original design
The original algorithms can still be used if each search node is changed from one location to a belief set. Searching over only one guessed location could produce a plan that fails when the guess is wrong. With k possible locations there can be up to 2^V belief sets in a general V-location problem, although only a small subset may be reachable.

C. Adaptation
Use belief-state search when no local sensor is available. If a local sensor can identify the actual junction, use a conditional plan: sense the current junction and then execute the route for that location. The sensor reduces uncertainty before movement. The demonstration uses a simple line of k junctions and a MOVE_LEFT action that shifts all hypotheses toward node 0; this is a deliberately small model, not a full hospital map.

D. Evidence
Run: python Task_12/Task_12.py
For k = 2, 4 and 8, the program reports the number of distinct belief states visited and the plan length without sensing, then the number of possible sensed hypotheses and worst-case movement count with a local sensor. The output screenshot is proof of this experiment. In this simplified line model both approaches require up to k-1 moves; the sensor's benefit is that it identifies the actual location and permits a location-specific conditional route. In a general hospital graph, sensing can reduce the belief-state search space substantially.
