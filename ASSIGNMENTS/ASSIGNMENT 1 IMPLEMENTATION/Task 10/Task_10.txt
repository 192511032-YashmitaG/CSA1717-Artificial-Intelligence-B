TASK 10 – COMPARE THEORY WITH EXPERIMENT

The graph is a deterministic tree, so each location has one route from the root and duplicate detection does not remove alternative paths. The measured generated and expanded counts therefore reflect the traversal order.

BFS expands all locations before the final target in breadth-first order on this test layout. Its frontier grows with the width of the tree, which is consistent with the theoretical warning that breadth-first search can require large memory.

Iterative DFS follows one branch at a time and in these runs reaches the final location after visiting fewer nodes than BFS. Its frontier is much smaller. This result is specific to the node numbering and neighbour order used in this generated tree; DFS is not generally faster and does not guarantee an optimal route.

Recursive IDDFS revisits shallow locations at each depth limit. Its generated-call count is therefore higher than a single depth-first pass, while the active path/frontier remains small. This matches the recurrence and the expected time-space trade-off.

Small timing differences should not be treated as universal. Python interpreter overhead, memory allocation, operating-system load and graph representation affect elapsed time. The operation counts and maximum frontier are more useful for comparing algorithm behaviour.
